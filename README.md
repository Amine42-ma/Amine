# DINO ROYALE EVOLUTION

**لعبة بقاء أونلاين بمنظور الشخص الأول، بأسلوب Block Style عالي الجودة، مع ديناصورات أصلية وعالم مفتوح ضخم.**

An original, fully online, first-person block-style survival battle royale. Everything —
world, creatures, weapons, textures, sounds, animations — is generated procedurally at
runtime from original designs. **No assets, maps, models, sounds, names or files are taken
from any other game.**

---

## ما الذي يميّز هذا المشروع

| | |
|---|---|
| **عميل واحد** | كل اللعبة داخل `index.html` واحد (لا مكتبات خارجية، لا CDN، لا ملفات صور أو صوت) |
| **خادم مرجعي** | Node.js بلا أي تبعيات (`npm install` غير مطلوب) — الخادم يقرّر كل شيء |
| **أونلاين بالكامل** | لا يوجد وضع أوفلاين؛ كل مباراة تعمل على خادم حقيقي بمزامنة 30 Hz |
| **عالم ضخم** | 6144 × 6144 بلوك، 16 منطقة حيوية، بدون شاشات تحميل بين المناطق |
| **بدون بث للتضاريس** | العميل والخادم يولّدان نفس العالم من نفس البذرة، فلا يُنقل سوى تعديلات اللاعبين |

## التشغيل السريع / Quick start

```bash
# 1. لا توجد تبعيات - فقط Node.js 20 أو أحدث
node --version

# 2. شغّل الخادم
npm start          # أو:  node server/server.js

# 3. افتح المتصفح
#    http://localhost:8080
```

للعب مع أصدقاء على نفس الشبكة، افتح العنوان الذي يطبعه الخادم (`http://<ip>:8080`).
للنشر على الإنترنت ضع الخادم خلف عاكس HTTPS (nginx / Caddy) وفعّل ترقية WebSocket.

### متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `8080` | منفذ HTTP + WebSocket |
| `HOST` | `0.0.0.0` | عنوان الاستماع |
| `DATA_DIR` | `./data` | مجلد تخزين الحسابات والعشائر |
| `MAX_CONNECTIONS_PER_IP` | `12` | حد الاتصالات لكل عنوان |

## بنية المشروع

```
index.html               ← اللعبة كاملة: الواجهة، المحرك، الشبكة، الصوت (ملف واحد)
server/
  server.js              ← HTTP + WebSocket + توجيه الرسائل
  lib/
    ws.js                ← تنفيذ WebSocket كامل (RFC 6455) بلا تبعيات
    store.js             ← تخزين مستندي مع كتابة ذرّية
    accounts.js          ← الحسابات، الجلسات، الاسترجاع، الخبرة، الإنجازات
    social.js            ← الأصدقاء، المجموعات، العشائر، النقابات، المحادثة
    matchmaking.js       ← الطوابير، الغرف الخاصة، حلقة المحاكاة
    match.js             ← محاكاة المباراة المرجعية (فيزياء، قتال، ديناصورات، العاصفة)
    voice.js             ← توجيه المحادثة الصوتية وإشارات WebRTC
    worldgen.js    (مشترك) ← توليد العالم الحتمي
    protocol.js    (مشترك) ← صيغة الشبكة وثوابت اللعب
    content.js     (مشترك) ← الأسلحة، الأدوات، الديناصورات، التقدّم
    movement.js    (مشترك) ← فيزياء الشخصية (تنبؤ + مرجعية)
tools/build-client.js    ← يُدرج الوحدات المشتركة داخل index.html
test/run.js              ← مجموعة اختبارات بلا تبعيات
```

الملفات المعلّمة بـ **(مشترك)** مُدرجة حرفياً داخل `index.html`. بعد أي تعديل عليها:

```bash
node tools/build-client.js      # يعيد إدراجها
node tools/build-client.js --check   # يتحقق فقط (للـ CI)
npm test                        # يتأكد أن النسختين متطابقتان على 120 ألف عيّنة
```

## المحرك الرسومي (WebGL2)

المسار الكامل لكل إطار:

1. **Depth + normal prepass** — early-Z ويغذّي الإظلام المحيطي
2. **SSAO** بنصف الدقة ثم تنعيم منفصل المحورين
3. **ظلال متتالية** (3 شرائح، 2048²، مثبّتة على البكسل لمنع الاهتزاز)
4. **سماء إجرائية** — تشتّت Rayleigh/Mie، قرص الشمس، القمر، النجوم، طبقتا سحاب
5. **تضاريس PBR** — GGX + Smith، خرائط normal، إضاءة voxel محسوبة بـ BFS، ضباب ارتفاعي
6. **نباتات alpha-tested** مع حركة رياح
7. **مياه** — انعكاسات فضاء الشاشة، انكسار، امتصاص حسب العمق، رغوة الشاطئ، بريق الشمس
8. **جسيمات** ناعمة (soft particles) بمزج إضافي
9. **معالجة لاحقة** — Bloom، TAA بإعادة إسقاط زمني، ACES tonemap، تدرّج لوني، FXAA

كل الخامات (61 مادة × albedo + normal + roughness/metal/emissive) تُولَّد رياضياً عند
الإقلاع — لا يوجد ملف صورة واحد في المشروع.

**متطلبات:** متصفح يدعم WebGL2 (Chrome/Edge 90+، Firefox 90+، Safari 15+).

## الشبكة ومنع الغش

الخادم هو المصدر الوحيد للحقيقة. العميل يرسل **النوايا فقط** (أزرار + زوايا النظر)،
ولا يرسل أبداً موقعه أو إصاباته أو غنائمه.

- **30 Hz** محاكاة على الخادم، **15 Hz** لقطات للعميل
- **تنبؤ محلي** لشخصية اللاعب باستخدام نفس ملف الفيزياء الذي ينفّذه الخادم، ثم مصالحة
  بإعادة تشغيل المدخلات غير المؤكَّدة (خطأ صفري عند التنبؤ الصحيح)
- **استيفاء زمني** 110 ms لبقية اللاعبين والديناصورات
- **تعويض التأخر** بإرجاع الخصوم حتى 260 ms عند حساب الإصابات
- **تحقق من كل شيء**: معدل الإطلاق، الذخيرة، مدى البناء، مدى التفاعل، حدود العالم
- **إدارة الاهتمام**: لا تُرسل إلا الكيانات ضمن 220 م
- **إعادة اتصال تلقائية** بتراجع أُسّي؛ الجسد يبقى في العالم 120 ثانية

لأن التضاريس حتمية على الجانبين، فإن حركة الشبكة داخل المباراة تقتصر على اللاعبين
والكيانات وتعديلات البلوكات — وليس على العالم نفسه.

## المحادثة الصوتية

الصوت ينتقل **مباشرة بين اللاعبين** عبر WebRTC (Opus، مع إلغاء الصدى وكبح الضوضاء)،
بينما يبقى الخادم مسؤولاً عن **من يسمع من**:

- `proximity` (Solo) — صوت مكاني ثلاثي الأبعاد ضمن 42 م
- `team` (Duo/Squad) — الفريق فقط
- `all` (Apex Hunt) — الجميع

يُطلب إذن الميكروفون **مرة واحدة عند أول تشغيل**؛ القرار يُحفظ في الحساب. الرفض يُبقي
الميكروفون مغلقاً تماماً مع إمكانية سماع الآخرين. يوجد كتم ذاتي، كتم لاعب معيّن (يُحفظ)،
وضع اضغط-للتحدث أو ميكروفون مفتوح.

الخادم يرفض تمرير إشارات WebRTC بين لاعبَين لا يشتركان في قناة — فلا يمكن التنصّت على
فريق الخصم.

## المحتوى

- **16 منطقة حيوية**: محيطات، شواطئ، سهول، غابات، أدغال، تايغا، ثلوج، صحارى، سافانا،
  مستنقعات، جبال، براكين، أنهار، جزر، أراضٍ وعرة، أنهار جليدية
- **7 أنواع معالم** مولَّدة إجرائياً: معابد، قواعد مهجورة، قرى مدمرة، مناجم عميقة،
  خزائن سرية، أعشاش، منصات بحرية — لكل واحدة تخطيط مختلف مشتق من بذرتها
- **8 ديناصورات أصلية** بسلوك مختلف (قطعان، كمائن، طيران، سباحة، زعيم)
- **13 سلاحاً + 23 أداة** مع 6 مستويات ندرة
- **61 نوع بلوك** قابل للبناء والتدمير
- **5 أنماط لعب**: Solo / Duo / Squad / Apex Hunt / غرفة خاصة

## الأداء

| الإعداد | الوصف |
|---|---|
| `low` | بدون ظلال/توهج/TAA، مقياس 0.72 |
| `medium` | ظلال منخفضة، SSAO، توهج |
| `high` (افتراضي) | ظلال 3 شرائح، SSAO، توهج، TAA، انعكاسات مياه |
| `ultra` | نفس `high` مع جسيمات أكثر |

التقطيع يعمل داخل Web Workers (عدد الأنوية − 1) مع تحميل حلزوني من موقع اللاعب للخارج،
فلا توجد شاشة تحميل بين المناطق.
